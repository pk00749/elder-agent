# v0.11.x bugfix 增量：保存后 LoadingState 全屏霸屏修复

> 对应 AGENTS.md §A.17 (v0.11.0) + 本 PR §A.18 (v0.11.x bugfix 例外) / prd.md §12.5 索引追加行。
> 本文件**只**定义产品 / 工程增量,具体代码约束在 AGENTS.md / prd.md。
>
> 本次主题:**`InterviewScreen` 保存后整屏卡在"加载中…"的根因修复 + `saveDiary` 状态机兜底 + `export` 超时保护**。
> 属于 v0.11.0 收尾 bugfix,**不动** §5 数据模型字段 / §3.1.4 A1–D3 既有行为约束 / §18 既有 lock。

## 1. 现象 (v0.11.0 终点 → v0.11.x 起点)

| 现象 | 复现路径 |
|------|----------|
| 老人点击保存后**整屏卡在"加载中…" + 进度条** | 进入访谈屏 → 录制 N 轮 → LLM 总结 → REVIEW 阶段 → 点 ✓ 保存 → 看到一整屏 loading,看不到 transcript / 错误 / 状态,主观"App 死了" |
| 极端情况:LoadingState 持续不消失 | LOCAL 模式 + Android 10+ scoped storage 失败 / CLOUD 模式 + OSS 网络挂死 → `exportIfNeeded` 永不返回 → state 卡在 `SAVED` → onDone 不触发 |

## 2. 根因分析 (按确定性排序)

### 2.1 布局 bug:`LoadingState().fillMaxSize()` 抢占 TranscriptCard 空间

- 文件:`app/ui/src/main/java/com/elder/ui/component/LoadingState.kt:18-19`、`app/src/main/java/com/elder/screen/interview/InterviewScreen.kt:189`
- 现象:`stage ∈ {PREPARING, SAVED}` 时,`LoadingState` 内部 `Modifier.fillMaxSize()` 在父 Column 末尾取走 `maxHeight`;`TranscriptCard(weight 1f)` 拿到剩余 = 0。
- 效果:老人看到的是**整个 inner Column**都被"加载中…" + 进度条占满,看不到任何 transcript 上下文,主观"卡在加载"。

### 2.2 状态机:`saveDiary` 在调 `onDone()` 之前先把 `stage = SAVED`

- 文件:`InterviewViewModel.kt:498-505`(原版)
- 现象:`_state.update { stage = SAVED }` 紧前于 `onDone()`,理论上能正确导航;但**整个 launch 段没有 try-catch / invokeOnCompletion 兜底**,任何子步骤抛异常都会让 state 停在 SAVED → 配合 §2.1 布局 bug → 老人看到整屏 loading。

### 2.3 缺超时:`saveExportRepo.exportIfNeeded` 是 suspend 阻塞调用

- 文件:`SaveExportRepository.kt:42-87`
- 现象:LOCAL 写 Downloads 在 Android 10+ scoped storage 下需要 MANAGE_EXTERNAL_STORAGE,没配的话 `writeText` 会抛 FileNotFoundException(已 catch);但 CLOUD 模式走 `syncDiary` 是 OSS 网络上传,**无超时保护**,挂死时 launch 永不返回。

### 2.4 `onEnter()` 抛异常让 `PREPARING` 阶段霸屏

- 文件:`InterviewViewModel.kt:90-164`(原版)
- 现象:`viewModelScope.launch { ... }` 没有 try-catch,`ServiceLocator.ttsClient()` / `metaRepo.ensureInitialized()` / `interviewRepo.active()` 等任意一个抛异常,state 停留默认 `PREPARING` → 配合 §2.1 → 老人看到整屏 loading(不限于保存场景,进访谈屏就卡)。

## 3. 关键改动 (增量)

### 3.1 修布局:用 `SavingStatusRow` 替换 `LoadingState`

- `app/src/main/java/com/elder/screen/interview/InterviewScreen.kt`
  - 删除:`InterviewStage.PREPARING, InterviewStage.SAVED -> LoadingState()`
  - 新增:`SavingStatusRow(stringResource(R.string.interview_saving_status))` —— 与 OPENING 阶段 `OpeningStatusRow` 同款 `PrimaryButtonHeight` 固定行高 Column
  - `SavingStatusRow` 本身是 InterviewScreen private composable,不动 LoadingState 公共组件(AGENTS.md §A.3 组件不可绕过 §4 规范"自创新规范")
- `app/src/main/res/values/strings.xml`
  - 新增:`<string name="interview_saving_status">正在保存…</string>`

### 3.2 修状态机:`saveDiary` 导出改成 sibling launch + `invokeOnCompletion` 兜底

- `app/src/main/java/com/elder/screen/interview/InterviewViewModel.kt`
  - 删除注释里误导的"不阻塞 onDone() 回调"—— 实现里就是同 coroutine 同步 await
  - 调整顺序:DB 写入 → `interviewRepo.save(...)` → `_state.update { stage = SAVED }` → **`onDone()`** → 后台 sibling `launch { runCatching { saveExportRepo.exportIfNeeded(...) } }`
  - 兜底:外层 `viewModelScope.launch { ... }.invokeOnCompletion { t -> if (t != null && t !is CancellationException) { Log.e + _state.update { stage = REVIEW, topError = "保存失败，请重试" } } }`

### 3.3 加超时:`saveExportRepo.exportIfNeeded` 走 `withTimeoutOrNull`

- `app/src/main/java/com/elder/data/export/SaveExportRepository.kt`
  - 新增 `companion object` 常量 `EXPORT_TIMEOUT_MS: Long = 3_000L`
  - 拆出 `private suspend fun runExport(diary, audioFile, mode): ExportOutcome` 容纳原有逻辑
  - `exportIfNeeded` 改为:`withTimeoutOrNull(EXPORT_TIMEOUT_MS) { runExport(...) } ?: ExportOutcome.Failed("EXPORT_TIMEOUT", "保存超时(3000ms)")`
  - 超时**不抛异常**(用 `withTimeoutOrNull` 不是 `withTimeout`),不污染调用方
- 新增单测:`com.elder.android.data.export.SaveExportRepositoryStructuralTest` 锁定 `EXPORT_TIMEOUT_MS=3_000L` + `withTimeoutOrNull` + `private fun runExport(` 结构
- 新增行为测试:`SaveExportRepositoryTest.export timeout returns Failed EXPORT_TIMEOUT when sync hangs` —— 注入 hang 5s 的 stub,断言 `Failed("EXPORT_TIMEOUT", ...)` + 总耗时 ≤ EXPORT_TIMEOUT_MS + 2s

### 3.4 `onEnter()` 加 try-catch 还原 READY

- `app/src/main/java/com/elder/screen/interview/InterviewViewModel.kt`
  - 拆出 `private suspend fun onEnterInternal()` 容纳原 launch 全部逻辑
  - 外层 `onEnter` 只做 `viewModelScope.launch { try { onEnterInternal() } catch (CancellationException) { throw } catch (Throwable) { Log.e + _state.update { stage = READY, topError = "初始化失败，请返回重试" } } }`
- 新增单测:`InterviewSaveFlowStructuralTest.onEnter_hasTryCatchRecoveredIntoReady` —— 源码扫描锁定 `fun onEnterInternal()` + `"初始化失败"` + `topError`

## 6. Assumptions & Defaults

1. **EXPORT_TIMEOUT_MS = 3_000ms**(对应 LOCAL 写 Downloads < 500ms + 3× 安全系数;CLOUD OSS 上传 > 3s 即视为挂死,放弃本次同步)
2. **`SavingStatusRow` 文案 = "正在保存…"**(沿用 `interview_opening_status` 的"…..."句式)
3. **`LoadingState` 公共组件不动**(AGENTS.md §A.3:`ElderDiaryRecordScreen` 等仍在用,且 §4.10 加载态规范不许改公共组件)
4. **兜底文案 `topError = "保存失败，请重试"`**(沿用 prd.md §3.1.4 B2 老人语言风格)
5. **§18 例外**:本次新增 `private suspend fun onEnterInternal()` 私有 suspend 方法、`SavingStatusRow` 私有 composable、`private suspend fun runExport` 私有方法。均在原文件 / 原组件内,不引新文件、不超 AGENTS.md §18 既有 lock
6. **不动 prd.md §5 数据模型字段**;Room schema 不变;**不动 §3.1.4 A1–D3 / B既有行为约束**
7. **不在 PR 内拆 InterviewViewModel**:超 500 行 123 行,在文件头注释记录触发 §18 拆分点的 v0.12.0 触发条件
