## A. 全局 UI 规范

### A.1 色彩 Token

| Token | 值 | 用途 |
|-------|----|----|
| `color.bg.primary` | `#FAF7F2` | 屏幕底色（暖白） |
| `color.bg.card` | `#FFFFFF` | 卡片底色（与暖白轻微反差） |
| `color.bg.elevated` | `#FFF4E6` | 高亮卡片底（就医提醒、待办） |
| `color.text.primary` | `#1F1F1F` | 主文字 |
| `color.text.secondary` | `#5A5A5A` | 副文字、说明 |
| `color.text.disabled` | `#9A9A9A` | 禁用态 |
| `color.brand.primary` | `#4A7A4A` | 墨绿主色——主按钮、激活态、强调 |
| `color.brand.primary_pressed` | `#3C623C` | 主按钮按下 |
| `color.accent.warm` | `#E07A3C` | 暖橙——就医提醒、辅助强调 |
| `color.danger` | `#C44545` | 警示——错误、删除、未应答 |
| `color.divider` | `#DCD5C9` | 分割线 |
| `color.shadow` | `rgba(31,31,31,0.08)` | 卡片阴影 |

对比度核查：所有文字/底色组合需 ≥ 4.5:1（WCAG AA）。`#5A5A5A` on `#FAF7F2` ≈ 7.6:1；`#4A7A4A` on `#FAF7F2` ≈ 4.8:1，符合。

### A.2 字号 Token（sp）

| Token | 值 | 用途 |
|-------|----|----|
| `font.hero` | **40** | 老人主屏问候（"早上好"） |
| `font.title` | **32** | 屏幕大标题（"该吃药啦"、"今日记录"） |
| `font.body` | **24** | 正文（卡片副标题、表单标签） |
| `font.caption` | **20** | 副文字、说明、时间戳 |
| `font.button` | **32** | 所有按钮文字 |
| `font.timer` | **48** | 录音时长显示 |

约束：以上为默认值；老人端设置可放大（见 §D.7）。家属端沿用相同字号（不放大）。

### A.3 间距 Token（dp）

| Token | 值 | 用途 |
|-------|----|----|
| `space.screen.padding_x` | 24 | 屏幕左右内边距 |
| `space.section.gap` | 24 | 屏内主要元素垂直间距 |
| `space.card.padding` | 20 | 卡片内边距 |
| `space.button.height` | **≥ 96** | 所有按钮高（含主屏写日记大按钮 120dp） |
| `space.button.gap` | 16 | 按钮组内间距 |
| `space.row.height` | 72 | 列表行高（提醒项、日志项） |

### A.4 圆角与动效

| 项 | 值 | 说明 |
|----|----|----|
| 卡片圆角 | **8 dp** | 不使用 16+ 大圆角（与老年克制气质保持一致） |
| 按钮圆角 | **8 dp** | 同上 |
| 元素入场动效 | ≤ 300 ms | 仅 fade / 极轻 slide；不引入弹性/缩放 |
| 提醒卡出现 | 全屏淡入 250 ms + 系统级震动 + TTS 立即播 |
| 加载态 | 转圈组件禁用；用「正在保存…」文字 + 进度条 | 转圈对老人不直观 |

### A.5 声音与反馈

| 场景 | 反馈 |
|------|------|
| 按钮按下 | 极短"哒"音 + 触觉反馈（light impact） |
| 录音开始/结束 | 短"嘟"音 + 触感（medium） |
| 任务完成（保存、应答） | 上扬"叮"音 + 触感（heavy） |
| 错误/失败 | 双短"嘟-嘟" + 触感 |
| TTS 播报 | 默认开启；老人端设置可关 |
| TTS 服务 | **千问 TTS**（DashScope / CosyVoice），默认音色 **粤语男声**（见 §H.15 决议） |

音量默认跟随系统媒体音量；不在 App 内提供"静音 App"开关（避免老人误关导致听不见提醒）。

## B. 启动与身份选择

### B.1 启动序列

1. **Splash**（2 秒，不可跳过）
   - 居中 Logo（"老友"二字 + 一片叶子图形）
   - 暖白底 `#FAF7F2`
   - 不出现版本号/广告/引导轮播
2. Splash 结束后判断本地状态：
   - 本地已存 `role`（`elder` / `family`）→ 直接进入对应主屏
   - 本地无 `role` → 进入身份选择屏（§B.2）

### B.2 身份选择屏

| 元素 | 规格 |
|------|------|
| 屏幕标题 | "您好，请选择身份"（32sp，居中） |
| 卡片 A：「我是老人」 | 高度 200dp，宽度 = 屏宽 - 48dp 内边距；圆角 8dp；白底；左侧大号人形图标 96dp；右侧"我是老人"32sp + 副文字"记日常、听提醒"20sp；点击进入老人主屏（**不走登录**，见 §B.3） |
| 卡片 B：「我是家属」 | 同高度；右侧"我是家属"32sp + 副文字"配提醒、看日志"20sp；点击进入家属登录流程（§C） |
| 两卡间距 | 24dp |
| 底部小字 | "不确定选哪个？"24sp + TTS 按钮 ▶（播报两段说明） |

不在此屏注册账号；账号创建时机见 §B.3 / §F。

### B.3 身份切换

老人/家属身份**不可在 App 内直接切换**。切换的唯一路径：进入对应端「设置 → 退出登录」→ 清空本地 `role` → 回到身份选择屏。

理由：MVP 不做多账号，单设备单身份最简单。

## C. 登录与鉴权流程（仅家属走 SMS）

> v2.0 §7.4 描述 JWT，本节落到 UI 流程。

### C.1 适用对象

| 端 | 登录方式 |
|----|----------|
| 家属 | SMS 验证码登录（强制） |
| 老人 | **首启不登录**；绑定时才生成 `elder_profile`（§B.3、§F） |

### C.2 手机号输入屏

| 元素 | 规格 |
|------|------|
| 顶部 | "请输入手机号"32sp 标题 |
| 输入框 | 大号数字键盘（`inputType="phone"`），字号 28sp；占位文字"11 位手机号"24sp 灰 |
| 按钮 | "获取验证码"——输入合法后高亮（墨绿），否则灰禁用；按钮高 96dp |
| 隐私小字 | "仅用于登录，不会发送广告短信"20sp 灰色，居输入框下方 |

### C.3 验证码屏

| 元素 | 规格 |
|------|------|
| 顶部 | "验证码已发送至 138****8888"24sp（自动遮中间四位） |
| 验证码输入 | **6 格独立输入框**，每格 64×80dp，字号 36sp；首格聚焦；输完自动提交 |
| 倒计时 | "59 秒后重发"20sp 灰；可点时变"重新获取"墨绿 |
| 按钮 | "登录"——6 位填满后高亮可点；或回车键自动提交 |
| TTS | 进入即 TTS 播报"验证码已发送，请在手机上查收" |

### C.4 失败与重试

- 验证码错误：底部 Toast "验证码不对，再试一次"24sp 1.5 秒；同时清空输入让老人重新输
- 60 秒内同一手机号重复请求：`429 RATE_LIMITED`，前端按 `retry_after_seconds` 禁用按钮
- 5 次失败锁定 5 分钟（v2.0 §6.1）：弹"请 5 分钟后再试"全屏提示卡 + TTS 播报

### C.5 登录成功

写入本地：`role=family`、JWT（v2.0 §7.4）、`family_user.id`；进入家属端主屏（§E.1）。

### D.1 主屏

布局自上而下：

```
┌─────────────────────────────────┐
│  区域 A：问候（高 200dp）        │
│   「早上好」  40sp 居中          │
│   「8 月 24 日 周一 09:12」20sp   │
│                                  │
├─────────────────────────────────┤
│  区域 B：今日提醒卡（高 120dp）  │
│   「下一项：吃阿莫西林 09:30」   │
│   或「今日暂无提醒」             │
│                                  │
├─────────────────────────────────┤
│  区域 C：写日记按钮（高 120dp）  │
│   「✎  按住说话写日记」          │
│   墨绿主色，文字 32sp 居中       │
└─────────────────────────────────┘
```

约束：
- 主屏元素 **恰好 3 个**（满足 v2.0 §4 第 2 条）；隐藏设置入口（连点中央 5 次）不计入
- 今日记录图标（决策 3）：保存日志后点亮——位置在 A 区右上角 32dp 图标位置；亮起 = 墨绿实心，未亮 = 灰色描边
- 写日记按钮按下：墨绿→`primary_pressed`，显示波形 + 时长（见 D.3）
- 设置入口：连点 A 区中央 5 次（每次间隔 ≤ 500ms）→ 进入 §D.7 隐藏设置；进入时震动 + TTS"打开设置"

边缘情况：
- 当前时间已有提醒触发中：主屏直接被全屏提醒卡覆盖（D.2 / D.5）
- 设备锁屏：提醒仍以系统通知形式弹出（见 §G.1）

### D.2 服药提醒全屏卡

| 区域 | 内容 |
|------|------|
| 顶部 | 系统状态栏 + 大铃铛图标 96dp（暖橙 `#E07A3C`） |
| 标题 | "该吃药啦" 32sp 居中 |
| 副标题 | "阿莫西林 · 1 粒" 24sp 居中（药名 + 剂量来自 reminder.payload） |
| 备注 | 有则显示，20sp 居中灰 |
| 主按钮 | "✓ 已吃"——高 120dp，墨绿底，32sp 白字 |
| 兜底 | 5 分钟无点 → 自动写入"未服药"ack；再 5 分钟再次响铃；30 分钟仍无应答 → 推送家属（v2.0 §11.2） |

行为：
- 弹出瞬间：震动 800ms + TTS"该吃阿莫西林了"
- 屏幕保持亮（`FLAG_KEEP_SCREEN_ON`）
- 点"已吃"：写 reminder_ack（`action=taken`）→ 播放上扬"叮" + 震动 → 卡片淡出 → 回到主屏
- 音量键/TTS 重复：右上角小图标"再听一遍"24dp，点击重播当前 TTS

**多药并发（§K.1a 决议）**：同一时刻触发 ≥ 2 条 reminder 时，**合并为一张卡**——主标题保持"该吃药啦"；副标题区按行纵列所有药名剂量（行高 48dp，字号 24sp，最多支持 4 种药；超出则拆第二张）；主按钮文案改为"✓ 全部已吃"——点击一次性 ack 所有；TTS 播报按顺序读全部药名。

**漏服回顾（§K.1c 决议）**：老人端**不展示**漏服统计（避免心理压力）；漏服 ack 写入后端，仅家属端可见。

**临时暂停（§K.1e 决议）**：老人端**不提供**暂停入口；暂停/恢复统一在家属端（§E.2 吃药项开关）。

**半粒视觉（§K.1f + §I-4.C 决议）**：主图标按剂量切换：
- "1 粒" → 整药丸
- "半粒" → 切半药丸（完整药丸 + 半药丸并列）
- "1 勺" → 药瓶 + 勺

> §I-4.C：移除"自定义"剂量档，特殊剂量由家属端"备注"字段承载。

### D.3 AI 访谈屏

布局：

```
┌─────────────────────────────────┐
│  进度条：「第 2 轮 / 共 8 轮」   │  ← 24sp 居中，灰
├─────────────────────────────────┤
│  Agent 回复区（高 200dp）        │
│   「今天都干啥了？」  32sp       │
│   ▶ TTS 播放中图标（脉动）       │
├─────────────────────────────────┤
│  老人本轮语音条（如有）          │
│   「……」（ASR 转写）  20sp 灰    │
├─────────────────────────────────┤
│  按住说话按钮（直径 160dp）      │
│   未按：灰底「按住说话」         │
│   按下：墨绿 + 波形条 + 时长     │
└─────────────────────────────────┘
```

逐轮状态机（按下 → 松开）：

1. **按下**（`onTouch DOWN`）：按钮变墨绿，开始录音（`MediaRecorder`，m4a）；开始计时；波形条启动
2. **松开**（`onTouch UP`）：停止录音 → POST `/v1/agent/asr`（音频已上传 COS）→ 拿 ASR 文字
3. **ASR 完成**：POST `/v1/agent/diary-session/:id/turn` 拿 Agent 回复（轮次未达上限）
4. **Agent 回复到达**：POST `/v1/agent/tts` 拿音频 → 立即播放 → 老人侧显示回复文字 + 播放脉动图标
5. **状态机推进**：进度条"第 N 轮 / 共 8 轮"刷新；按钮回到"按住说话"
6. **收尾触发**（满足 §3.1.4.C 任一）：跳到 D.4 总结屏

异常处理：
- ASR 失败：弹出"没听清，再说一次"大按钮（96dp 高）；老人按下后回到本轮重新录音，不消耗轮数
- Agent 30 秒超时：v2.0 §3.1.2 兜底——TTS 播"今天到这儿吧，明天继续" + 自动跳 D.4
- 老人中途退出（按返回）：保存已有 turns → status=`abandoned`，回到主屏

**方言 ASR（§K.2e 决议）**：服务端 ASR 走**千问 ASR**，**主识别粤语**（与 TTS 粤语男声统一调性）；普通话自动兜底识别。其他方言（四川话、上海话等）若 ASR 置信度 < 0.6，弹"听不太清，再说一次"走录音重试流程（不消耗轮数）。

**多人说话（§K.2d 决议）**：**不支持 VAD 切分**，整体录音 + 整体 ASR；Agent 收到长文本后由 LLM 自行归纳为老人视角的日记。家庭同堂场景提醒：可由老人事先告知"等家人走了再按"。

**录音技术规格（§L.3 决议 + 后台录音方案 D）**：
- API：`MediaRecorder`，输出 AAC/m4a（与 v2.0 §5.8 COS key 后缀一致）
- 采样率 / 编码：16 kHz / 单声道 / 64 kbps——够 ASR + 省流量
- 屏幕保持亮：`FLAG_KEEP_SCREEN_ON`（v2.0 §D.3 已要求）
- 单轮时长硬限：**60 秒**——到时震动 + TTS"时间到，松手吧"+ 自动停止
- 应用进入后台（`onStop()`）：立即停止 → 保存已录音频 → 弹"录音被打断，回到主屏"
- 系统来电打断：同上走 §D.3 中途退出流程（保存已有 turns → status=`abandoned`）
- 录音失败：自动重试一次，仍失败走 §D.3 ASR 失败兜底
- 录音中顶部状态条："正在录音… 00:23"（红色脉冲，字号 32sp）
- 麦克风权限拒绝（§G.1）：弹"需要麦克风权限才能写日记"+ 跳转系统设置

**为什么不上前台 Service（方案 D 决策依据）**：Android 14 `FOREGROUND_SERVICE_TYPE_MICROPHONE` 启动后必须保持 Activity 可见，否则杀服务——老人一切后台就失效；国内厂商 ROM 自启动 / 电池优化适配成本高；业务上单轮 < 60s 不需要长录音。

MVP 仅保留 §F.3 扫码绑定一种方式。§E.1 未绑定态只保留「扫码绑定」卡片，「输入手机号」入口在 MVP 不渲染。

实现备忘（v2.2 落地时参考）：家属输入老人手机号 → 后端发送短链 → 老人点短链唤起 App → 进入 §F.4 确认；老人未装 App 时仅给"请先安装老友 App"+ 应用商店链接。

### F.3 方式 B：扫码绑定

家属侧流程：
1. 在 §E.1 点「扫码绑定」→ 调起相机（见 §G.1 权限）
2. 扫老人设备 §D.7 第 4 项生成的二维码（内容含 `device_token` + 临时 `bind_code`，5 分钟有效）

老人侧流程：
1. 进入 §D.7 第 4 项「生成本机二维码」→ 后端签发 `bind_code` → 在老人设备显示二维码（中心嵌 Logo）
2. 等待被扫（5 分钟内）；后台开始轮询 `/v1/bind/pending`（10 秒一次）
3. 收到扫到通知 → 弹 §F.4 确认卡（**队列模式，§F.3 决议 23**：一次只显一张，同意/拒绝后出下一张；如无下一张则关闭弹窗）

**等候屏视觉（§F.3 决议 22）**：老人设备显示一个**全屏遮罩**：
- 居中显示大二维码（边长 60% 屏宽，中心嵌 App Logo）
- 顶部 16sp 灰字倒计时「MM:SS 后过期」
- 底部「取消」按钮（96dp 高，墨绿描边）
- 倒计时归零：自动 Toast「二维码已过期，重生成」5 秒 + 「重生成」主按钮（96dp 高，主色填充）
- 倒计时归零前二维码持续 10 秒/次轮询 `/v1/bind/pending`；扫描成功后遮罩消失，进入 §F.4 单卡确认

**等候期间交互（§F.3 决议 24）**：全屏遮罩拦截触摸事件；物理返回/Home 键**不取消流程**——仅退出遮罩，`bind_code` 仍保留 5 分钟有效；老人再次进入 App 时：仍在 5 分钟内 → 直接回到等候屏或 §F.4 确认卡；已过期 → 回 §D 主屏 + Toast「二维码已过期，重生成」5 秒。

### F.4 老人侧绑定确认卡

| 元素 | 内容 |
|------|------|
| 标题 | "XX 想绑定" 32sp（XX = `family_user.name`；缺则回退手机号尾四位如 "136****8888"；§F.4 决议 25 砍掉「儿子/女儿」关系词，MVP 不引 `relation` 字段） |
| 副文字 | "绑定后，XXX 可以给您设置提醒、看您记的日志" 20sp 灰 |
| 按钮 A | "同意"——墨绿，96dp 高 |
| 按钮 B | "拒绝"——描边灰，96dp 高 |

点击"同意"时（决策 2）：
- 老人端体验（§F.4 决议 28）：**全屏过渡 1 秒** + 主屏从 §D.7（未绑定态）切到 §D.1（待提醒主屏）；**不要震动 + TTS**——避免老人启动瞬间被打断
- 流程：
1. 客户端调 `POST /v1/bind/confirm`，body`{ bind_code, elder_name }`
2. 后端在该事务内**同时**：
   - 创建 `elder_profile`（含 `name`、可选 `phone`、`device_token`、`timezone`）
   - 创建 `binding`（`role=primary`）
   - 返回 `elder_id`、`binding_id`
3. 老人端写入本地 `elder_id` + JWT；主屏更新绑定状态
4. 家属端收到推送/轮询"绑定成功"→ 进入 §E.1 已绑定态

点击"拒绝"（§F.4 决议 26）：
- 后端立即将该 `bind_attempt` 标记为 `rejected` + `bind_code` 失效
- **不创建** `elder_profile` 也不创建 `binding`
- 老人端弹简短过渡卡 "已拒绝"+ TTS 播报 → 1.5 秒后关闭弹窗回到主屏
- 家属端收到推送 "对方未同意，请确认在场后再扫"+（同一 `bind_code` 已失效，需重新生码）
- **拒绝无理由选项**（§F.4 决议 27）：MVP 不引入"不认识/再想想/选错"理由；UX 简单，避免老人端多一步操作

**Primary vs Secondary（§H.25 决议）**：
- 同一 `elder_profile` 上，**首个完成老人同意的家属 = primary**（有解绑权，见 v2.0 §11.6）
- 后续家属邀请自动降级为 secondary；老人侧弹单卡"XXX 想添加为家庭成员"（与首位邀请文案差异：标题无"主"字、副文字改为"可帮您设提醒、看日志，但不能解除其他家庭成员"）
- secondary 邀请**仍需老人同意**（隐私敏感，不绕过）

### F.5 老人设备未绑定时的本地状态（§H.24 决议）

老人首启到绑定成功之间，存在以下本地状态：
- 本地有 `role=elder` + `device_token`，**无** `elder_id`
- 主屏"今日提醒卡"显示"等待家人配置提醒"
- 写日记按钮可用，录音 → ASR → 转写 → **暂存本地 Room 表 `pending_diary`**（不上传匿名 bucket），绑定成功后由 `flush_pending_diaries()` 批量 POST `/v1/diary`（带 `pending_id` 去重）

Room schema：
```
pending_diary(
  id           TEXT PRIMARY KEY,  -- 客户端 UUID
  created_at   INTEGER,           -- epoch ms
  audio_cos_key TEXT,             -- 已上传 COS 的临时音频 key（24h 过期）
  turns_json   TEXT,              -- Turn[] 序列化
  text         TEXT,
  summary      TEXT,
  status       TEXT               -- 'pending' | 'synced' | 'dropped'
)
```

未绑定时退出 App / 卸载 App：本地 Room 数据丢失，§D.7 第 6 项「退出登录」+「卸载 App」前应再次提示"未上传的日记会丢失"。

### M2 提醒下发机制（混合 push + 拉取）

**C 方案**——三层兜底：

1. **Push 即时**：家属 POST `/v1/reminders` → 服务端立刻 TPush 自定义消息 → 老人设备收到 → 立即 INCREMENTAL 同步 + 注册本地闹钟
2. **启动 / 网络恢复全量拉**：App 启动 / `onResume` / 网络恢复时 GET `/v1/reminders?from=today&days=14`，diff vs 本地闹钟表
3. **定时兜底**：每 6 小时 WorkManager periodic task → FULL_SYNC

设备侧同步状态机：

```
IDLE
 ├── on TPush custom message received → INCREMENTAL_SYNC
 ├── on app start / onResume / network recovered → FULL_SYNC
 └── every 6h (WorkManager periodic) → FULL_SYNC

FULL_SYNC:
  GET /v1/reminders?from=today&days=14
  diff vs 本地闹钟表:
    新增 → AlarmManager.setExactAndAllowWhileIdle(token)
    修改 → cancel old + set new
    删除 → cancel

INCREMENTAL_SYNC (from push payload):
  payload = { reminder_id, action: 'create|update|delete' }
  GET /v1/reminders/:id 详情 → 注册 / 更新 / 取消闹钟
```

依赖：§H.18 两条 TPush 通道（服药中优 / 就医高优）需支持自定义 payload；云端可控。

### M3 JWT 续签机制（双 token）

**B 方案**——access_token 1h + refresh_token 30d，OkHttp 拦截器无感续签。

| Token | 规格 |
|-------|------|
| **access_token** | HS256；payload = `{ user_id, role, elder_id?, exp=now+1h }`；Header `Authorization: Bearer <access>` |
| **refresh_token** | HS256；payload = `{ user_id, role, jti, exp=now+30d }`；一次性使用（每次 refresh 都轮换新 refresh） |
| **refresh 撤销列表** | CloudBase 简单集合 `revoked_refresh_jti`，登出 / 改密时写入 |
| **存储** | DataStore + EncryptedSharedPreferences 加密 |

端点：
- `POST /v1/auth/login`（v2.0 §6.1）→ 返回 `{access, refresh}`
- `POST /v1/auth/refresh`（新增）→ 用 refresh 换新 access + 新 refresh（轮换）
- `POST /v1/auth/logout`（新增）→ 撤销 refresh + 清本地

OkHttp 拦截器逻辑：
```
request → 检查 access 是否 < 5min 过期
  是 → 用 refresh 换新 access（并发锁避免重复刷新）
  否 → 直接发
response 401 → refresh 再换一次；换失败则跳登录
```

风险点：
- refresh 重放：用 jti 单次有效 + 设备指纹绑定
- access / refresh 同时过期（30d 不使用）→ 走 SMS 重登录

### N1 绑定通知实时性

| 项 | 规格 |

不选 WS（心跳耗电、Android 后台断线率高）或 10s 轮询（实时性差）。

### N2 音频上传中断

**A 方案**——单次上传 + 失败重试 3 次（指数退避 1s/3s/9s）。

每轮上传流程：
1. POST `/v1/agent/diary-session/:id/upload-url` 拿预签 COS URL（5 分钟有效）
2. PUT 上传 m4a（超时 30s）
3. 失败 → 指数退避重试最多 3 次
4. 仍失败 → 弹"上传失败，是否重试？"（已成功的 turn 保留不丢）
5. 成功 → 调 `/turn` 端点拿 Agent 回复

切后台特殊处理：§L.2 录音中切后台 → 立即停止 + 中途退出；已上传 turn 保留 COS tmp 目录（24h 生命周期）；重新进入访谈屏 → 提示是否继续未完成 session。

### N3 老人端 diary 同步幂等

**A 方案**——客户端 UUID（`pending_diary.id`）作为 `Idempotency-Key` header。

```
flush_pending_diaries():
  for pending WHERE status='pending':
    POST /v1/diary
      Header: Idempotency-Key: <pending.id>
      Body: { elder_id, session_id?, text, summary, audio_segments[] }
    200 → 拿到 diary_id → status='synced'，存 server_diary_id
    409 → 服务端已处理同 key → 返回旧 diary_id → status='synced'
    5xx / 网络错 → status 保持 pending，下次 flush 重试
```

服务端实现要点：
- CloudBase `idempotency_keys` 集合（key + elder_id 联合索引）
- diary_entry 表加 `idempotency_key` 字段
- 写入新 entry 与 idempotency_key 同事务，失败回滚
- 幂等键永久保留（空间开销极小）

### N4 JWT 过期边界

**B 方案**——OkHttp Authenticator + Interceptor 双保险 + 单飞锁。

| 层 | 职责 |
|----|------|
| **Interceptor** | 主动检测 access 即将过期（`exp - now < 5min`）→ 提前 refresh |
| **Authenticator** | 401 兜底 → refresh 后重试原请求 |
| **单飞锁** | `Mutex` 串行化 refresh；30s 去抖避免重复刷新 |
